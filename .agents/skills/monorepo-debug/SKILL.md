# Диагностика ошибки в монорепозитории

Выполняй работу последовательно.

## 1. Исследование

* Сначала проверь состояние Git.
* Используй codebase-memory-mcp для поиска связанных пакетов, файлов, функций, обработчиков, маршрутов и тестов.
* Определи точку входа проблемной функции.
* Найди вызывающие и вызываемые функции.
* Не выполняй рекурсивное чтение всего репозитория.
* Не изменяй код на этом этапе.

## 2. Определение причины

* Прочитай только реализации найденных функций.
* Сопоставь ожидаемое и фактическое поведение.
* Проверь конфигурацию, регистрацию обработчиков, порядок middleware, условия, исключения и связанные тесты.
* Назови конкретную причину ошибки и доказательства.
* Если причина ещё не подтверждена, продолжай диагностику без изменения кода.

## 3. План исправления

До редактирования перечисли:

* затронутые пакеты;
* изменяемые файлы;
* изменяемые функции;
* связанные тесты;
* возможные побочные эффекты.

## 4. Исправление

* Внеси минимальное изменение.
* Не выполняй несвязанный рефакторинг.
* Не меняй публичные интерфейсы без необходимости.
* Добавь или обнови минимальный регрессионный тест.

## 5. Проверка

* Используй RTK для команд Git, поиска, тестов, линтеров и сборки.
* Сначала запусти только связанные тесты.
* Не запускай весь набор тестов без необходимости.
* Проверь текущий Git diff.
* Через codebase-memory-mcp оцени влияние изменения на вызывающие функции, маршруты и пакеты.

## 6. Итог

Сообщи:

* найденную причину;
* изменённые файлы;
* выполненное исправление;
* запущенные тесты и их результат;
* оставшиеся риски.
