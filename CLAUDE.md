# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Проект и документация на русском — отвечай пользователю по-русски.

## Что это

wtbot — Discord-бот + веб-дашборд + фоновые парсеры в одном процессе
(модульный монолит). Собирает реплеи клановых боёв War Thunder с
warthunder.com, разбирает бинарные файлы реплеев `.wrpl` и рисует
картинки с результатами боя (аналог закрытого бота «Boris Stats»).
Данные копятся в SQLite как датасет для будущего обучения нейросети.

## Команды

```bash
npm run dev               # бот + сайт (:3000) + парсеры, перезапуск при изменениях
npm run deploy:commands   # регистрация slash-команд (после любого изменения команд!)
npm run battle            # таблица боя из реплея; флаги: -- <sessionId> --image --media --json
npm run analyze           # анализ записей через Claude API (нужен ANTHROPIC_API_KEY)
npm run build && npm start  # продакшен-сборка
```

Тестов и линтера нет. Проверка — запуском: рецепт в `.claude/skills/verify/SKILL.md`
(готовность `curl http://localhost:3000/health`, что смотреть в логах и API).

Нужен Node ≥ 22.5 (`node:sqlite`, `zstdDecompressSync`). Предупреждение
`ExperimentalWarning: SQLite` при старте — норма.

## Архитектура

Один процесс (`src/index.ts`) поднимает три модуля, которые общаются
**только через `src/db/`** (node:sqlite, WAL, без ORM) и явные интерфейсы
(`WebDeps`, `ParserSource`). Это осознанно: модули можно разнести на
отдельные процессы, а SQLite заменить на Postgres, трогая только `src/db/`.

Конвейер данных:

```
парсеры (по интервалам) → items (пачки в одной транзакции,
  дедуп по UNIQUE(source, external_id) + content_hash)
  → analyses (Claude, 1 запись = 1 анализ, кэшируется навсегда)
  → сайт и бот только читают готовое из БД
```

- `src/parsers/sources/` — активен только `wt-replays`. Новый источник:
  файл, экспортирующий `ParserSource` (скелет — в README, «Как добавить
  парсер») + запись в массив в `sources/index.ts`.
- `src/bot/commands/` — команда: файл + запись в массив в `commands/index.ts`
  + `npm run deploy:commands`.
- `src/web/routes/` — JSON API (`/api/stats`, `/api/items`, `/api/voice`)
  и дашборд (одна HTML-страница строкой в `pages.ts`, без сборщика).
- `src/bot/voice-tracker.ts` — кто сидит в голосовых каналах (интент
  GuildVoiceStates, не privileged): пишет в таблицу `voice_presence`,
  дашборд читает через `/api/voice`. Ник в игре — из серверного ника
  «WTНик (Имя)» (до первой скобки). Статистика игрока — из своих данных
  (ПКР+клан из снимков, бои из items); профиль на сайте WT закрыт
  Cloudflare-челленджем, туда не ходим. `WT_VOICE_CHANNELS` в `.env`
  ограничивает каналы, пусто — все.

## Парсер wt-replays и формат .wrpl

- API сайта отдаёт списки боёв **только с куками залогиненной сессии**
  (`WT_COOKIE` в `.env`; анонимам — 200 с пустым списком). Сессия скользящая:
  сервер продлевает её каждым ответом (+14 дней), `wt-cookies.ts` подхватывает
  Set-Cookie и хранит актуальные куки в `data/wt-cookies.json` — куку вставляют
  один раз, обновление нужно только после простоя >14 дней или отзыва сессии.
  Новая строка в `.env` имеет приоритет над сохранённым состоянием (поле seed).
  Протухла кука → источник кидает ошибку «обнови WT_COOKIE», видно на дашборде.
  User-agent в парсере должен соответствовать браузеру, из которого кука.
- Парсинг инкрементальный: `hasItem()` по sessionId, обход страниц
  прерывается на первой уже известной записи, паузы 400 мс между запросами.
- `src/wrpl/` — разбор бинарного `.wrpl` (портировано с Go-библиотеки
  wrpl-inspector, **AGPL-3.0** — при публичном распространении бота код
  придётся открыть; наземные позиции — с WrplReplayParser, BSD-3-Clause):
  заголовок 1226 байт с фиксированными смещениями; results-BLK (таблица
  игроков) — в конце **последней** части реплея, формат BLK разбирает
  `blk.ts` (FAT/FAT_ZSTD). Пакетный поток (zlib со смещения
  `1234 + settingsBlkSize` в каждой части, части конкатенируются)
  разбирает `replay-events.ts`: слоты игроков, убийства с координатами,
  повреждения, чат, победитель (награда `hidden_win_streak`), траектории —
  авиация из пакетов типа 2 (лётная модель), наземка из MPI-сообщений
  GMSync `02 58 74 f0` (`gm-sync.ts`: дельта-компрессия против кольца из
  32 состояний юнита, XOR-патч + битовый RLE-кодек rle0ki). ECS-сущности
  (`ecs.ts`) связывают uid юнита с моделью техники и слотом игрока; словарь
  хэшей компонентов — `data/ecshashes.json` (качается из wrpl-inspector,
  после крупного патча игры удалить для обновления). Сигнатуры MPI-сообщений
  дрейфуют между версиями игры (позиции были `a3 f0`, стали `74 f0`) — при
  пустых траекториях на свежем патче искать новые id в WrplReplayParser.
- Battle log и хитмапы: `render-battle-log.ts` (хронология убийств),
  `render-heatmap.ts` (траектории на карте: mode ground/air, черепа в
  цвете погибшего со значком причины смерти — силуэт класса убийцы или
  тип ГСН ракеты для авиации (ИК/ПАРЛ/АРЛ из rocketguns датамайна через
  `ensureWeaponSeekers`, кэш `data/weapons.json`; ЗУР зениток — по имени
  оружия, звезда — разбился), пунктирные линии фрагов от убийцы к жертве,
  пятна стоянок ≥1 мин с длительностью (наземка, путь обрезан по смерти —
  остов шлёт статичную позицию), зоны A/B/C, метки минут вдоль траекторий;
  наземная карта — во весь кадр, воздушная — по габаритам полётов;
  справа инфопанель: карта/режим/дата/длительность, команды в порядке
  сторон на карте с отметкой победителя, по игроку — фраги/смерти,
  техника, очки и время гибели, внизу блок условных обозначений;
  16 уникальных цветов игроков, подобраны max-min поиском
  по OKLab ΔE). Границы карты и зоны — из файла миссии
  (`mission-info.ts`; путь лежит в заголовке реплея, JSON качается из
  датамайна, кэш `data/missions/`). Многие миссии описывают battleArea
  не у себя, а в шаблонах из `imports` (`template_*_battleareas.blk`) —
  они качаются тоже, а имя области выбирается как в движке:
  `*battle_area_realistic` → `_arcade` (`battlearea_exclude_*` — вырезы,
  не границы). Фон — снимок игровой карты нужного
  режима из коллекции wt-tools.app (`ensureTacticalMap` в
  `battle-assets.ts`: ключ карта+режим из missionName, бакет
  storage.googleapis.com/wt-map-files, кэш `data/maps/`); снимок покрывает
  ровно battleArea, чужой режим не подставляется (на нём запечены зоны
  и спавны той миссии). В датамайне текстур тактических карт нет —
  клиент рендерит их из геометрии уровня, поэтому источник внешний. Сборку и кэш всего комплекта делает
  `battle-media.ts` (`data/battles/<sid>-*.png|.txt`): в боте — кнопки под
  `/battle` (View Chat / Battle Log / Heatmap ×2, ответы ephemeral),
  роутер кнопок в `bot/index.ts` по префиксу customId `battle:`; в CLI —
  `npm run battle -- --media`. Части реплея живут на CDN ~2 недели, при
  скачивании CDN отвечает 429 на параллельные запросы — качать
  последовательно (fetchReplayParts уже делает паузы и ретраи).
- `src/wrpl/vehicles.ts` — словарь техники (id → название/класс/страна):
  при первом запуске качает ~40 МБ из датамайна War-Thunder-Datamine,
  кэширует в `data/wt-vehicles.json`, исходники удаляет.
- `src/wrpl/render-battle.ts` — картинка боя в стиле Boris Stats: SVG
  собирается строками, растеризуется через `@resvg/resvg-js` с системными
  шрифтами (CJK-ники рендерит Microsoft YaHei). Боты `coop/*` в таблицу
  не попадают. Команда с большей суммой очков — слева («золотая»).
  Платформа игрока — суффикс ника `@psn`/`@live`. Игрок без единой машины
  в бою или запись matchingInfo без строки результатов → красный значок +
  `Disconnected` / `Unknown Player` (такая запись дописывается в неполную
  команду, при равных составах не показывается).
- Украшения клан-тегов (`╖VCoM╖` → ⚔VCoM⚔) — box-drawing символы
  U+253A…U+2560, их рисует шрифт игры `symbols_skyquake.ttf`:
  `wt-fonts.ts` достаёт его из `ui/fonts.vromfs.bin` клиента War Thunder
  (поиск в Steam-библиотеках / `WT_GAME_DIR`, распаковщик — `vromfs.ts`),
  кэш `data/fonts/`. Без шрифта — юникод-замены `DECOR_MAP` (ими же
  украшаются теги в текстах Discord и консоли).
- Личный клановый рейтинг (колонка ⊛, дельта за бой сверху): в реплее его
  нет — источник `wt-clans` (каждые 12 ч) строит из лидерборда сайта словарь
  «тег → имя клана» (таблица `clans`), а `src/wrpl/clan-info.ts` при рендере
  берёт рейтинги со страницы `claninfo/<имя>` (кулдаун 2 мин/клан) и пишет
  снимки в `clan_rating_snapshots`; дельта = разница двух последних снимков
  ника, появляется со второго увиденного ботом боя клана.
  `battle-assets.ts`: силуэты техники из датамайна (кэш `data/unit-icons/`),
  фон — скриншот карты из `data/maps/<level>.jpg`, иначе градиент.

## Конвенции

- ESM (`"type": "module"`): в импортах расширение `.js`, даже из `.ts`.
- Строгий tsconfig (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`):
  индексация массивов возвращает `T | undefined` — проверяй или `!`.
- Комментарии, логи, тексты команд и README — по-русски.
- Весь SQL живёт в `src/db/index.ts`; остальной код зовёт его функции.
- `data/` и `.env` в .gitignore: БД, кэш словаря, куки сессии, PNG боёв, секреты.
  В `.env` уже заполнены TOKEN, CLIENT_ID, GUILD_ID, WT_COOKIE.
