# wtbot

Discord-бот с веб-дашбордом, фоновыми парсерами и анализом данных нейросетью.
Один процесс, конвейер данных:

```
[сбор]              [хранение]              [обработка]           [показ]
парсеры ────────→ SQLite: items ────────→ анализ (Claude) ────→ сайт и /stats
(фоново, по        (пачки в транзакции,    (отдельно, 1 запись   (читают готовое —
 интервалам)        дедупликация по хэшу)   = 1 анализ, кэш)      мгновенно)
```

Почему это быстро:

- пользователь никогда не ждёт парсинга — сайт и бот читают готовое из БД;
- записи пишутся пачками в одной транзакции — тысячи строк за миллисекунды;
- дедупликация: повторный парсинг пропускает неизменившиеся записи;
- нейросеть работает отдельно и каждый результат кэшируется в БД навсегда;
- SQLite в WAL-режиме тянет миллионы строк; когда станет мало — меняется
  только `src/db/` на Postgres, остальной код не трогается.

## Структура

```
src/
  index.ts              — точка входа: поднимает БД, бота, сайт и парсеры
  config.ts             — все переменные окружения в одном месте
  db/index.ts           — общий слой хранения (node:sqlite): статистика, items, анализы
  bot/
    index.ts            — Discord-клиент и обработка команд
    deploy-commands.ts  — регистрация slash-команд в Discord
    commands/           — сами команды (/ping, /stats)
  web/
    index.ts            — сборка fastify-сервера
    routes/api.ts       — JSON API (/api/stats, /api/items, /health)
    routes/pages.ts     — дашборд на /
  parsers/
    index.ts            — планировщик: запускает источники по интервалам
    sources/            — источники: wt-replays (реплеи клановых боёв War Thunder)
                          + wt-cookies (автопродление сессии сайта)
  wrpl/
    blk.ts              — разбор бинарного формата BLK (Gaijin) — портирован с wrpl-inspector
    replay.ts           — контейнер .wrpl: заголовок и results-BLK (таблица результатов боя)
  analysis/
    analyze-items.ts    — анализ собранных записей через Claude (npm run analyze)
```

## Быстрый старт

Нужен **Node.js ≥ 22.5** (используется встроенный SQLite; предупреждение
`ExperimentalWarning: SQLite` при старте — норма).

1. [Discord Developer Portal](https://discord.com/developers/applications) → своё приложение:
   - **Bot → Reset Token** → это `TOKEN`
   - **General Information → Application ID** → это `CLIENT_ID`
2. Скопируй `.env.example` в `.env` и заполни. `GUILD_ID` (ID тестового сервера) — опционально, но с ним команды появляются мгновенно.
3. Пригласи бота на сервер (подставь свой Application ID):
   `https://discord.com/oauth2/authorize?client_id=ТВОЙ_APPLICATION_ID&scope=bot+applications.commands&permissions=0`
4. Установка и запуск:

```bash
npm install
npm run deploy:commands   # регистрирует /ping и /stats в Discord
npm run dev               # запускает бота + сайт + парсеры с перезагрузкой при изменениях
```

Дашборд: http://localhost:3000 · API: http://localhost:3000/api/stats и /api/items

## Скрипты

| Команда                   | Что делает                                        |
|---------------------------|---------------------------------------------------|
| `npm run dev`             | запуск в разработке (tsx watch)                   |
| `npm run deploy:commands` | регистрация slash-команд (после их изменения)     |
| `npm run analyze`         | анализ 3 новых записей нейросетью (`-- 20` — 20)  |
| `npm run battle`          | таблица результатов боя из реплея (`-- <id>`, `--image`, `--json`) |
| `npm run build`           | компиляция в `dist/`                              |
| `npm start`               | запуск собранной версии (продакшен)               |

## Парсер War Thunder (wt-replays)

Каждые 5 минут собирает свежие реплеи клановых боёв с
`warthunder.com/en/tournament/replay/`: метаданные боя (карта, режим, время,
версия игры), составы обеих команд и прямые ссылки на файлы реплея `.wrpl`.
Всё складывается в таблицу `items` с дедупликацией по `sessionId` — каждый
бой хранится один раз.

API отдаёт данные только залогиненным, поэтому нужна кука сессии в `.env`
(`WT_COOKIE`, см. `.env.example`). Вставить её достаточно один раз: сессия
скользящая — сервер каждым ответом продлевает её ещё на 14 дней, а бот
подхватывает обновлённые куки (Set-Cookie) и хранит их в `data/wt-cookies.json`,
как это делает браузер. Если бот всё же простоял выключенным больше 14 дней
или сессия отозвана (например, сменился пароль), источник на дашборде станет
красным с ошибкой «обнови WT_COOKIE» — зайди на сайт в браузере и скопируй
свежие куки; новое значение в `.env` подхватится автоматически. Парсер нарочно
вежливый: 2 страницы списка за цикл, пауза 400 мс между запросами, детали
качаются только для новых боёв.

Из самих файлов `.wrpl` можно достать полную таблицу результатов боя
(фраги/ассисты/захваты/смерти/очки/техника каждого игрока) — это делает
`npm run battle` (модуль `src/wrpl/`). Формат разобран по образцу
Go-библиотеки [wrpl-inspector](https://github.com/maxsupermanhd/wrpl-inspector)
(AGPL-3.0). Лог убийств и траектории движения лежат в пакетном потоке
реплея (zlib) — их разбор сложнее и ещё не портирован.

`npm run battle -- --image` рисует таблицу PNG-картинкой (в стиле Boris
Stats) в `data/battles/`, а команда бота **`/battle [id]`** присылает её
в Discord вместе с текстом: кланы, состав и игроки обеих команд. На картинке:
клан-теги с украшениями (⚔…⚔), флаги наций команды, состав (4F/3T/1AA),
силуэты техники (качаются из датамайна по мере надобности, кэш —
`data/unit-icons/`), значки платформ у консольных игроков (суффиксы
`@psn`/`@live` в нике) и колонки возд./назем./ассисты/захваты/смерти.
Слева — команда с большей суммой очков (обычно победитель; честного
признака победы в results-BLK нет). Показывается **первая машина сетапа**
игрока — какая техника реально использовалась, лежит в пакетном потоке,
который ещё не разбирается.

Фон картинки — скриншот карты, если положить его в `data/maps/<level>.jpg`
(например `data/maps/avg_guadalcanal.jpg`; внутреннее имя карты печатает
`npm run battle` и содержит заголовок реплея). Нет файла — рисуется
тёмный градиент.

Названия и классы техники берутся из словаря, который при первом запуске
собирается из датамайна игры
([War-Thunder-Datamine](https://github.com/gszabi99/War-Thunder-Datamine),
~40 МБ одноразово) и кэшируется в `data/wt-vehicles.json`. Рендер —
SVG → PNG через `@resvg/resvg-js`, шрифты системные (китайские ники
рисуются через Microsoft YaHei).

## Как добавить парсер

1. Создай `src/parsers/sources/имя.ts` — экспортируй объект `ParserSource`
   (живой пример — `wt-replays.ts`):

   ```ts
   import type { ParserSource } from '../types.js'

   export const mySource: ParserSource = {
     name: 'my-source',          // уникальное имя — попадает в БД и статистику
     intervalMs: 10 * 60_000,    // как часто запускать
     async run() {
       const res = await fetch('https://example.com/api/posts')
       if (!res.ok) throw new Error(`HTTP ${res.status}`)
       const posts = (await res.json()) as { id: number; title: string }[]
       return {
         summary: `Получено: ${posts.length}`,
         items: posts.map((p) => ({ externalId: String(p.id), title: p.title, data: p })),
       }
     },
   }
   ```

2. Впиши его в массив в `src/parsers/sources/index.ts`.

Каждая запись — это `{ externalId, title, data }`. `externalId` — уникальный
ид на источнике (url, id из API): по нему работает дедупликация. В `data`
клади любые поля — они сохраняются как JSON и отдаются через `/api/items`.

Сводка запуска (`сохранено: N, без изменений: M`) видна на дашборде и в `/stats`.

## Анализ нейросетью

`npm run analyze` берёт записи, которые ещё не анализировались, отправляет их
в Claude и сохраняет результат в БД. Анализ виден на дашборде (🧠 под записью)
и в `/api/items`. Каждая запись анализируется **один раз** — результат кэшируется.

Нужен ключ: [platform.claude.com](https://platform.claude.com/) → API Keys →
добавь в `.env` строку `ANTHROPIC_API_KEY=sk-ant-...`. Без ключа всё остальное
работает как обычно.

Промпт и модель — в `src/analysis/analyze-items.ts`. Когда захочешь
автоматизировать — вызывай анализ по интервалу из `src/index.ts`, как парсеры.

## Как добавить команду бота

1. Создай `src/bot/commands/имя.ts` по образцу `ping.ts`:

   ```ts
   import { SlashCommandBuilder } from 'discord.js'
   import type { Command } from '../types.js'

   export const hello: Command = {
     data: new SlashCommandBuilder().setName('hello').setDescription('Поздороваться'),
     async execute(interaction) {
       await interaction.reply('Привет!')
     },
   }
   ```

2. Впиши её в массив в `src/bot/commands/index.ts`.
3. `npm run deploy:commands`.

## Куда развивать

- **Больше данных War Thunder**: wt-replays собирает только свежие бои; можно
  добавить обход старых страниц (бэкфилл всех ~53 тыс. реплеев) и скачивание
  самих файлов `.wrpl` по ссылкам из `data.replayParts`.
- **Дашборд «как у juniper»**: вход через Discord OAuth2, страницы настроек
  per-guild. Место под это — `src/web/routes/`, таблица `guild_settings` в БД.
- **Автоанализ**: запускать `analyzeBatch` по интервалу или после каждого парсинга.
- **Рост нагрузки**: SQLite → Postgres (меняется только `src/db/`); процесс
  можно разделить на два (`бот+парсеры` и `сайт`) — модули уже независимы.
