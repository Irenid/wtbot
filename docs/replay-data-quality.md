# Заметки о качестве данных реплеев

> Черновые наблюдения автора (июль 2026), перенесены из `src/bot/my.md`. Цифры относятся к выборке того времени.

4. Траектории намеренно прореживаются.
   Точка сохраняется при интервале не менее 500 мс или смещении не менее 4 м по горизонтали; координаты округляются (src/wrpl/replay-events.ts:554). Точные ускорения, мелкие манёвры и packet-level поведение восстановить нельзя.

5. Зоны — только статические точки.
   Даже если ECS найдёт зону, нет временной истории захвата. В текущей выборке 200 последних боёв зон вообще не было.

6. 6.Теряются отдельные поля игрока.
   autoSquad не попадает в battle_players; номер слота и часть slot metadata остаются только в blob.

7. Часть сохранённых колонок не возвращается read-моделью.
   game_version записывается в battles, но getBattleForRender() его не выбирает. При реконструкции заголовка версия становится 0, а autoSquad — false (src/wrpl/battle-data.ts:136).
9. Каналы чата не валидируются.
   По контракту допустимы 0–3, но в БД есть 91 значение вне этого диапазона.


Качество нормализованных данных:

- 56 боёв имеют team_won = 0; это нужно считать «победитель неизвестен», а не поражением;
- 53 боя без status;
- только 7 без mission_settings;
- 172 игрока отмечены отключившимися;
- 99,2% игроков имеют clan tag;
- 97,3% убийств имеют обе позиции;
- у 10,5% убийств отсутствует victim_id;
- у 5,2% отсутствует weapon.



### Что уже полезно без изменения схемы

Надёжнее всего использовать:

- win rate по командам и кланам;
- kills/assists/deaths/score по игрокам;
- lineup техники и эффективность первой машины;
- участие игрока и disconnect rate;
- kill graph по userId и времени;
- kill positions и расстояния между участниками;
- базовые ground/air heatmap с фильтром userId != '';
- сопоставление battle-статистики с clan rating snapshots;
- контроль качества parser/injest по заполненности ID, позиций и ошибок.

С оговорками:

- damage — только как индикатор critical/severe pressure;
- траектории — для маршрутов, зон активности и heatmap, но не для точной физики;
- чат — для временной корреляции тактики, с отдельной политикой приватности;



То есть это описание положения зоны на карте, а не журнал захвата: кто начал захват, когда, какая команда контролировала точку и когда потеряла её.

Кроме того, текущий renderer для отображения capture-зон использует данные миссии (mission.zones), а не events.zones из replay. Поэтому нулевое число зон в 200 последних blob не означает, что на картах нет зон.

### 2. autoSquad и номер слота

autoSquad действительно разбирается из results-BLK, но затем не записывается в battle_players. При реконструкции боя значение принудительно становится false (src/wrpl/battle-data.ts:136).

Это влияет только на аналитику:

- автоматический или ручной squad;
- состав и стабильность отрядов;
- сравнение squad play против одиночной игры.

Для текущего scoreboard и win rate это несущественно. В коде сейчас нет реального потребителя autoSquad, поэтому приоритет низкий.

Номер slot, title и часть slot metadata не потеряны полностью — они находятся в events_blob. Но SQL-запросом их получить нельзя без распаковки blob.

Исправлять стоит, если планируется squad-аналитика или нужно полностью восстанавливать исходный results-BLK. Тогда лучше добавить:

- auto_squad INTEGER NULL;
- при необходимости slot и title в отдельную таблицу.

Для старых боёв autoSquad почти наверняка нельзя восстановить: в blob его нет, а .wrpl после успешного ingest удаляется. Для новых боёв это можно сохранить без большой переделки.







Исправлять стоит, если нужны:

- временная шкала захвата;
- анализ эффективности атак/обороны вокруг зон;
- автоматический разбор тактики по capture points.
## Сверка сбора 2026-10-01

- **Неполные реплеи.** Replay API показывает ~2% боёв ещё до их конца:
  `partsCount` и `endTime` такой записи ранние. Разбор без последних частей
  берёт промежуточные итоги из части 0001: ~95 с, `battles.status` NULL, нет
  победителя. Пример: в записи 12 частей, на CDN 16; 12 частей дают 95 с без
  победителя, 16 — 711 с и победителя. С 2026-10-01 ingest ищет недостающие
  части на CDN и не пишет бой без финальных итогов, миграции v12–v14 вернули
  такие бои на переразбор. Бой без исхода по времени тоже пишет финальные
  итоги без статуса (пример: 25 минут, timePlayed 1513 с при 1509 с по
  записи); от промежуточных их отличает время. Июльские «53 боя без status» выше, вероятно, того
  же происхождения; проверить нельзя, частей на CDN уже нет.
- **Пропуск 2026-08-02 … 2026-09-23.** Боёв за эти дни нет: бот не работал,
  а части на CDN живут ~2 недели. Первые три недели сезона 62 (с 2026-09-01)
  в датасете отсутствуют. Поэтому у клана, игравшего только тогда (лидер
  сезона AVR, 2545 боёв, официальная статистика без изменений с 2026-09-29),
  на сайте нет ни одного боя.
- **История официального рейтинга кланов** начинается 2026-09-29, поэтому
  дельта «за 30 дн.» появится не раньше 2026-10-29.
- **Текст лидерборда** (регион, слоган, награды) приходил экранированным для
  HTML и с разметкой игры (`&lt;color=#…&gt;`). С 2026-10-01 он чистится при
  сборе; строки кланов, выпавших из обходов, остаются прежними, но сайт их не
  показывает.
